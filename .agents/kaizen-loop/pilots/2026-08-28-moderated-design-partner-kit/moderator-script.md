# 主持人脚本

## 会前 10 分钟

1. 确认本地地址 `http://localhost:15175/llm-space-web/#/workbench` 返回 200。
2. 使用新鲜浏览器上下文，确认工作台显示 20/20 免费额度。
3. 准备 `after-sales-pilot-bundle.json`，不要打开或展示其 JSON 正文。
4. 关闭通知、私人标签页和可能暴露敏感信息的窗口。
5. 打开远程控制或准备同机浏览器；不要让参与者控制终端。

## 0:00–3:00 开场

读出：

> 今天我们测试的是产品，不是你。请你亲自操作并边做边说。遇到问题时，先说出你期待的下一步，然后再请求提示。本次只用虚构售后数据，请不要粘贴任何真实客户或公司资料。

阅读隐私说明并获得口头同意。如果不同意，立即停止。

## 3:00–6:00 恢复试点

1. 从参与者点击“导入试点包”开始计时。
2. 让参与者阅读完整内容警告，并用自己的话说明试点包与脱敏报告的区别。
3. 参与者选择试点包并确认恢复。
4. 当界面显示第二轮、10 个 Case 和“待评审 (10)”时停止计时。
5. 记录恢复秒数、是否主动找到入口、计数是否一致和提示次数。

成功标准：不超过 180 秒，且预览为 1 Thread、2 实验、10 Case、40 Run、10 已有人工评审。

## 6:00–16:00 人工评审

1. 从参与者打开“待评审 (10)”开始计时。
2. 请参与者至少打开一次 Baseline Trace 和一次 Candidate Trace。
3. 不解释快捷键，除非参与者明确请求提示。
4. 第 5 条完成后，请参与者刷新页面，自行返回评审队列。
5. 待评审清零时停止计时。

成功标准：不超过 600 秒，刷新后仍为已评 5 / 待评 5，且无人工替代操作。

## 16:00–21:00 门禁与晋升

1. 问：“现在你认为 Candidate 能否进入下一轮？为什么？”
2. 让参与者打开晋升确认，说出哪些字段会变更。
3. 如果门禁通过，让参与者应用 Candidate，并确认下一轮草稿与原实验谱系。
4. 刷新并确认当前 Thread Prompt 与下一轮草稿仍存在。

如果参与者做出与内部验收不同的评审结论，不要纠正。记录门禁是否阻止以及参与者是否理解原因。

## 21:00–25:00 导出与追问

1. 让参与者分别导出完整试点包和脱敏报告。
2. 问：“哪个文件可以发给更广泛的利益相关者？为什么？”
3. 问北极星三问：能否解释门禁、是否愿意 14 天内第二轮、付费方式偏好。
4. 请参与者只选一个最大阻塞：入口/导入、隐私/交付、评审效率、质量门禁理解、第二轮重复劳动，或无价值。

## 提示规则

- 第一次求助：只问“你期待在哪里找到它？”，记为 1 次轻提示。
- 第二次求助：指出区域，不代点，记为 1 次方向提示。
- 第三次求助：才能说出具体入口，记为 1 次直接提示，该任务不再计入“无协助完成”。
- 只有安全、隐私或数据丢失风险才可以立即打断。
