# 三场试点后的决策规则

完成 3 场外部试点前，不启动新的主要产品能力。不使用内部验收数据代替外部样本。

## 先检查北极星

| 问题 | 目标 |
| --- | --- |
| 3 名设计合作伙伴是否均完成首轮？ | 3/3 |
| 恢复 `<= 3 分钟` 且评审 `<= 10 分钟` | 至少 2/3 |
| 14 天内完成同 Case Set 第二轮 | 至少 2/3 |
| 明确付费或延长试点 | 至少 1/3 |

## 主决策树

1. **如果至少 2 人的最大阻塞是 `entry_import`**：下一轮做导入引导与试点恢复可发现性，不做云分享。
2. **如果至少 2 人的最大阻塞是 `privacy_handoff`**：先定义受控分享、权限、过期、撤销和审计边界，再提案云项目分享 V1。
3. **如果至少 2 人的最大阻塞是 `review_speed`**：优先优化批量选择、队列筛选和评审信息密度，不立即引入 LLM judge。
4. **如果至少 2 人的最大阻塞是 `gate_comprehension`**：做门禁原因总结、阻止解释和晋升前检查清单。
5. **如果至少 2 人的最大阻塞是 `repeat_effort`**：调查可重现执行、定时/按需回归或 Headless CI，但先明确凭据、密钥和失败契约。
6. **如果至少 2 人选择 `no_value`，或 3 人都不愿付费/延长**：停止功能开发，回到问题访谈和客户细分，不用更多功能补救定位问题。
7. **如果无一类阻塞达到 2 人**：不以单一用户结论开发。再补 2 名同一客户细分的样本，然后重新决策。

## 回归护栏

- 确定性回归继续阻止晋升，人工评审不能覆盖它。
- 不上传完整试点包到未经批准的云服务。
- 不把主持人代点或直接提示后的结果计为无协助完成。
- 不在没有重复外部证据时提案登录、团队、账单、云分享或 CI 执行。
